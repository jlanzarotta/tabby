Fuzzy tab completion for the commands you actually use.

Tabby learns the commands you run successfully and brings them back with a few keystrokes and the Tab key. Type a short query such as gco, press Tab, and Tabby expands it to the best matching command, for example git checkout main. Press Tab again to cycle through the other matches. When nothing matches, normal shell completion takes over.

Features

  • Fuzzy matching on word starts, so dcu finds docker compose up -d.

  • Ranking by frecency: how often and how recently you ran a command.

  • Directory-aware ranking: commands you ran in the current directory, or elsewhere in the same git repository, rank above commands you ran somewhere else.

  • Pinning: pinned commands never expire and do not lose rank as they age.

  • Learning from your picks: when you cycle to a command and run it, Tabby offers it first the next time you type the same query.

  • Next-command prediction: press Tab on an empty prompt to get the commands that usually follow the one you just ran.

  • Usage statistics with alias suggestions for the long commands you run most.

  • Only successful commands are recorded. Failed commands are never stored.

  • Exclusion patterns that keep secrets and noise out of the store, with a large built-in set.

  • Integration for Zsh, Bash, and PowerShell.

  • A single local SQLite database. Nothing leaves your machine.

Install

From the repository root:

go install ./cmd/tabby

Make sure $(go env GOPATH)/bin is in your PATH.

Shell setup

Zsh

Add to ~/.zshrc:

eval "$(tabby init zsh)"

Bash

Bash 4.4 or newer is required.

Add to ~/.bashrc:

eval "$(tabby init bash)"

PowerShell

PowerShell 5.1 or newer and PSReadLine 2.0 or newer are required. PSReadLine is installed by default.

Add to your PowerShell profile:

Invoke-Expression (& { (tabby init powershell | Out-String) })

Key bindings

Key Action

Tab

Expand the query to the best match. Press again to move to the next match.

Shift+Tab

Expand to the last match, or move to the previous match.

Tab on an empty prompt

Insert the command that most often follows the last command you ran. Press again to move to the next prediction.

Tabby only completes when the cursor is at the end of the line. Otherwise, and whenever there is no match, the key falls back to the shell’s normal completion.

How it works

Recording

After each command finishes, the shell integration checks its exit status. When the command succeeded, the integration runs tabby add in the background. Tabby then stores the command along with:

  • how many times it has been used and when it was last used, and

  • the directory it ran in and the root of the git repository around that directory, if there is one, and

  • the query, when the command was inserted by Tabby and you ran it without changing it. See Learned picks.

  • the command you ran just before it in the same shell, if it was stored. See Next-command prediction.

Matching

  • Queries are case-insensitive.

  • The characters of the query must appear in the command in order, and the first one must start a word. For example, gco matches git checkout main, and bdr does not match bun run dev.

  • A query must be at least two characters long, must not contain whitespace, and must not look like a path. Paths such as ./build, ~/src, or C:\temp are left to the shell.

  • At most 50 matches are returned.

Ranking

Commands you have picked for the exact same query come first. See Learned picks. All other matches are ordered by how well the text matches:

  1. matches that land on more word starts,

  2. then matches with more consecutive characters,

  3. then matches with fewer gaps.

Ties are broken by a score. The base score is the use count multiplied by a recency weight:

Last used Weight

Within the last hour

4

Within the last day

2

Within the last week

0.5

Longer ago

0.25

Tabby then adds the command’s recent use in the current location:

  • Use in the current directory counts 4 times: once for the directory and once for the repository.

  • Use elsewhere in the same git repository counts once.

Each of these is also a use count multiplied by the recency weight above. So a command you run often in this repository wins a tie against one you run often somewhere else.

A pinned command never gets a recency weight lower than 2, so it ranks as if it had been used within the last day.

Apart from learned picks, text match quality always comes first. A better fuzzy match from anywhere beats a weaker match from the current directory. Directory use and pinning decide the order among equally good matches.

How directories are compared

  • The repository root is the closest directory at or above the current one that contains a .git entry.

  • A repository at your home directory is ignored, so a dotfiles repository there does not make every directory count as one project.

  • On Windows, paths are compared case-insensitively.

  • Commands recorded before directory tracking was added have no directory data. The directory boost builds up as you use the shell.

Learned picks

When you press Tab, cycle to a command, and run it exactly as Tabby inserted it, Tabby remembers that you picked that command for that query. The next time you type the same query, the picked command is offered first. This fixes the cases where the fuzzy ranking puts the command you want further down the list, and it needs no setup.

  • Picks are tied to the exact query, ignoring case. A pick for dcu does not affect dc or dcud.

  • When several commands have been picked for the same query, they are ordered by how often and how recently you picked them, using the same recency weights as above. They all come before commands that were never picked.

  • Picks do not depend on the directory. A command picked in one repository is offered first for that query everywhere.

  • A pick is only recorded when the command succeeds and you did not edit the line. Accepting the first match also counts, which keeps it first.

  • Picks expire after a month without use, and are deleted with their command.

If Tabby learned the wrong command, run tabby forget <query> to start over for that query.

Next-command prediction

Each shell remembers the last command you ran successfully. When you run the next one, Tabby records that it followed the previous one. Press Tab on an empty prompt, and Tabby inserts the command that most often follows the last command you ran, for example git commit right after git add ., or podman push right after podman build. Press Tab again to cycle through the other predictions.

  • Predictions are ordered by how often and how recently that command followed the previous one, using the same recency weights as above. Ties go to the command with the higher overall score.

  • Each shell tracks its own previous command, so commands run in two terminals at once do not mix. A new shell has no previous command until you run one.

  • A failed command breaks the chain: the next command is not recorded as following anything.

  • A command that is not stored, because it is too short, hidden, or excluded, also breaks the chain. For example, nothing is learned across a cd, since cd * is excluded by default.

  • Running the same command twice in a row is not recorded, because up-arrow already covers that.

  • When there is no previous command or no prediction for it, Tab on an empty prompt falls back to normal shell completion.

  • Follow-ups expire after a month without use, and are deleted with either of their commands.

To see the predictions without the shell, run tabby next "<command>".

What is not stored

  • Commands that did not finish successfully

  • Commands of five characters or fewer

  • Commands that run tabby itself, or that contain control characters

  • Commands that match an exclusion pattern

  • In Zsh and PowerShell, commands that start with a space. Bash follows HISTCONTROL instead, so set HISTCONTROL=ignorespace (or ignoreboth) to get the same behavior.

  • In PowerShell, commands that the PSReadLine AddToHistoryHandler keeps out of the history file. By default, that handler skips lines that look like they contain secrets.

Retention

Commands that have not been used in the last month are deleted, unless they are pinned. Directory usage, learned picks, and follow-ups older than a month are deleted too, including for pinned commands. Cleanup runs each time a command is recorded.

Commands

Shell integration

tabby init <shell>

Print the integration script for zsh, bash, or powershell. See Shell setup.

Command history

tabby add "<command>"

Record a run of a command, as if it had just finished successfully in the current directory. The same rules apply as for automatic recording, so a command that is too short or excluded is silently ignored.

tabby remove "<command>"

Delete a stored command, including its directory usage, its learned picks, its follow-ups, and its pin.

tabby query "<query>"

Print the matching commands in ranked order, one per line, using the current directory for ranking. The shell integration calls this when you press Tab.

tabby next "<command>"

Print the commands that usually follow a command, most likely first, one per line. At most 50 are printed. The shell integration calls this when you press Tab on an empty prompt.

tabby list

List stored commands with their last-used time and score, highest score first. Pinned commands are marked [pinned]. The scores shown here do not include directory use.

Option Description

--pinned

List only pinned commands.

tabby forget [query]

Forget the commands learned for a query, so that it ranks normally again. Tabby prints how many picks were deleted.

Option Description

--all

Forget the learned picks for every query. It cannot be combined with a query.

tabby stats

Show a summary of the store, the most used commands, and alias suggestions. The counts cover the last month, plus pinned commands.

Option Description

--top <n>

Number of most used commands to show. The default is 10. Use 0 to hide the list.

--shell <shell>

Syntax for the alias suggestions: zsh, bash, or powershell. The default is powershell on Windows and zsh everywhere else.

Alias suggestions list up to five commands that are at least 15 characters long and have been run at least five times, the ones that would save the most typing first. Each suggestion is named after the first letter of each word, for example dcudb for docker compose up -d --build. When that name is already a program on your PATH, or is used by an earlier suggestion, a number is added, for example gssb2.

For Zsh and Bash, a suggestion is an alias line. Arguments you type after the alias are passed on to the command. For PowerShell, it is a function, because PowerShell aliases cannot include arguments. Arguments typed after the function name are not passed on.

Example output:

Usage over the last month, plus pinned commands

Commands stored:    214 (3 pinned)
Runs recorded:      1532
Learned picks:      12
Learned follow-ups: 87

Most used:
     87  2026-11-17 09:12  docker compose up -d --build
     64  2026-11-17 08:55  go test ./...

Alias suggestions:
  docker compose up -d --build (87 runs)
    alias dcudb='docker compose up -d --build'

Tabby does not add aliases for you. Copy the ones you want into your shell profile.

tabby pin "<command>"

Pin a command so that it never expires. If the command is not stored yet, it is added. Pinning is refused for a command that matches an exclusion pattern.

Pinning is meant for commands you run rarely but do not want to retype, such as a release or certificate renewal command.

tabby unpin "<command>"

Unpin a command so that it expires normally again. It is an error to unpin a command that is not pinned.

If an unpinned command has not been used in the last month, it is deleted the next time any command is recorded.

Exclusions

Exclusions are case-insensitive glob patterns, not regular expressions. They support (any text), ? (any single character), and […​] (any character in the set, or not in it when the set starts with ^). A pattern must match the whole command, so most patterns start and end with .

tabby exclude add "<pattern>"

Add an exclusion and delete every stored command that matches it, including pinned commands. Tabby prints how many commands were deleted.

Option Description

--force

Allow a pattern that matches every command, such as *. Without it, such a pattern is refused, because it would delete all history.

tabby exclude remove "<pattern>"

Remove an exclusion. Commands it kept out in the past are not restored.

tabby exclude list

List the exclusion patterns with the time each was added, newest first.

Built-in exclusions

The built-in exclusions cover:

  • cd * and ls *

  • names and options that usually carry secrets, such as API_KEY, --api-key, *_TOKEN, token=, PASSWORD, passphrase, --secret, and private-key

  • Authorization: headers, credentials in URLs (https://user:pass@host), curl -u, sshpass, and -p password options for MySQL and MariaDB

  • SQL Server tools (sqlcmd -P, bcp, sqlpackage), sqlplus, mongosh, and connection strings with Pwd=

  • redis-cli -a and valkey-cli -a

  • registry and cluster logins with -p for Docker, Podman, Buildah, Skopeo, Helm, oc, and az

  • container and Kubernetes secrets (secret create, --from-literal)

  • Vault and OpenBao logins and writes, rabbitmqctl add_user, and net use /user:

  • well-known token prefixes such as ghp_, gho_, github_pat_, glpat-, xoxb-, xoxp-, and sk_live_

  • PEM blocks (-----BEGIN)

Run tabby exclude list to see the full set.

Other commands

tabby path

Print the absolute path to the SQLite database. See Storage.

tabby prepare

Create the database and apply any pending schema migrations, then exit. Every other command that uses the database does this too, so you only need it to set up the database ahead of time.

tabby --version

Print the version, build date, and license. tabby -version also works.

Environment variables

Variable Description

XDG_CONFIG_HOME

When set to an absolute path, the database is stored in $XDG_CONFIG_HOME/tabby, on every platform. Relative values are ignored.

TABBY_DIR

The directory to use for directory-aware ranking. When it is not set, Tabby uses its working directory. The PowerShell integration sets it, because Set-Location does not change the working directory of the PowerShell process. The Zsh integration sets it to the directory the command started in.

TABBY_QUERY

Used by the PowerShell integration to pass the query that a command was picked for, with --from-env on add.

TABBY_PREVIOUS

Used by the PowerShell integration to pass the previous command, with --from-env on add.

TABBY_INPUT

Used by the PowerShell integration to pass the command or query text, with the hidden --from-env option on add and query. PowerShell 5.1 does not escape embedded quotes in arguments to native commands, so the text goes through the environment instead.

Storage

The database is a single SQLite file named tabby.db.

Platform Location

Any, with XDG_CONFIG_HOME set

$XDG_CONFIG_HOME/tabby/tabby.db

Windows

%AppData%\tabby\tabby.db

macOS

~/Library/Application Support/tabby/tabby.db

Linux

~/.config/tabby/tabby.db

On Linux and macOS, the directory is created with mode 0700 and the database files with mode 0600, so only you can read them. On Windows, Tabby relies on the permissions of your user profile.

The schema is upgraded automatically when a newer Tabby opens the database. An older Tabby refuses to open a database created by a newer one, and asks you to upgrade.

Cautions

The database is not encrypted. Every stored command is kept in plain text, together with the directories it ran in. Anyone who can read your user configuration directory, or a backup of it, can read your command history.

The built-in exclusions are not exhaustive. They catch common ways that secrets appear on a command line, but not all of them. Add your own patterns for anything sensitive, and prefer reading secrets from files or environment variables over typing them on the command line.

Hiding a command differs by shell. In Zsh and PowerShell, starting a command with a space keeps it out of Tabby. In Bash, this only works when HISTCONTROL includes ignorespace or ignoreboth.

Exclusions delete history. Adding an exclusion permanently deletes every stored command it matches, including pinned commands. Removing the exclusion later does not bring them back.

Directory paths are stored too. Directory-aware ranking records the full path of each directory you run commands in. Folder names can reveal client or project names.

Learned picks and follow-ups are stored too. Each pick stores the query you typed next to the command, and each follow-up stores which command you ran right after which, in the same unencrypted database. Together they show the order of your work, not only what you ran.

Check alias names before using them. Suggested names are only checked against programs on your PATH. They can still clash with shell built-ins, existing aliases and functions, or PowerShell’s built-in aliases such as gc, gp, and sl.

Tab is taken over. Tabby binds Tab and Shift+Tab, including on an empty prompt when it has a prediction. In Bash, Tab is bound to menu-complete, which cycles through completions instead of listing them.
